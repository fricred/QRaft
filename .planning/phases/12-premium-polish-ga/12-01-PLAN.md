<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RevenueCat SDK → App Store / Play Store | Purchase verification happens server-side at RevenueCat; client only reads CustomerInfo |
| isPremiumProvider → ad suppression | Premium check is local; RevenueCat CustomerInfo is the source of truth |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Tampering | isPremiumProvider spoofed by debug build | accept | Server-side entitlement validation at RevenueCat; premium features are cosmetic/UX improvements not transactional, so client bypass has minimal business impact |
| T-12-02 | Information Disclosure | REVENUECAT_API_KEY in client | accept | RevenueCat public API key (not secret key) is intentionally client-side per RevenueCat architecture; read-only for fetching offerings; secret operations happen server-side at RevenueCat |
| T-12-03 | Elevation of Privilege | User purchases then refunds to keep premium | mitigate | RevenueCat webhook (not implemented in v1.0) would update Supabase; accepted risk for v1.0 — RevenueCat handles entitlement revocation; app re-checks CustomerInfo on launch via SubscriptionSyncService |
| T-12-04 | Denial of Service | Ad load before consent | mitigate | Existing UmpGate (Phase 1 plan 05) blocks all ad loads; isPremiumProvider check is additional suppression |
</threat_model>
