| order data → operator screen | All orders readable by operator (all user_id values) — requires bypassing user-scoped RLS (plan 11-03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Elevation of Privilege | transition_order RPC | mitigate | RPC already has GRANT EXECUTE to service_role only (T-10-15); plan 11-03 adds operator_role check; consumer app cannot call this from regular auth session |
| T-11-02 | Information Disclosure | operatorOrdersProvider fetching all orders | mitigate | plan 11-03 creates operator_role RLS bypass; standard user RLS policy still blocks non-operator sessions |
| T-11-03 | Tampering | operator client sends arbitrary newStatus string | mitigate | transition_order RPC enforces FSM CHECK constraint server-side; invalid transitions raise Postgres exception rejected by Dart layer |
| T-11-04 | Denial of Service | stale-order query scanning full orders table | accept | idx_orders_ops_queue index on (status, created_at) added in Phase 9 migration; operator traffic is low-volume (single operator) |
