`WompiWebViewScreen` is a `ConsumerStatefulWidget` that receives a `CheckoutSession`
via its constructor.

Constructor:
```dart
const WompiWebViewScreen({super.key, required this.session});
final CheckoutSession session;
```

`initState`:
- Create a `WebViewController`.
- Set `JavaScriptMode.unrestricted` (required for Wompi's hosted page).
- Set `NavigationDelegate`:
  - `onNavigationRequest`: intercept any URL that STARTS WITH
    `WompiConfig.checkoutRedirectUrl` (`qraft://payment-result`).
    On match:
    1. Parse the URL for `id` query param (Wompi appends `?id=wompi_tx_id`).
    2. Call `Navigator.of(context).pushReplacement(MaterialPageRoute(
         builder: (_) => PaymentResultScreen(
           orderId: session.orderId,
           transactionRef: session.transactionRef,
         )))`.
    3. Return `NavigationDecision.prevent`.
    All other URLs: return `NavigationDecision.navigate`.
  - `onPageStarted`: set `_isLoading = true` → rebuild.
  - `onPageFinished`: set `_isLoading = false` → rebuild.
  - `onWebResourceError`: show error SnackBar with message, then pop.
- Call `controller.loadRequest(Uri.parse(session.wompiCheckoutUrl))`.

`build`:
- Scaffold with AppBar title "Pagar con Wompi", leading back button that shows
  a confirmation dialog ("¿Cancelar el pago?") before popping to prevent accidental
  dismissal.
- Body: Stack of [WebViewWidget(controller: controller),
  if (_isLoading) centered CircularProgressIndicator with neon Color(0xFF00FF88)].

Semantics identifier on the WebViewWidget: `wompi_webview`.

Note on PSE/Nequi: PSE redirects the user OUT of the WebView to their bank's website
and back. Wompi handles this transparently within the WebView session. Nequi shows a
push-notification confirmation step; the WebView will poll and display the result.
Both flows end with the same redirect to `qraft://payment-result` when complete or
timed out. No special handling needed beyond the above intercept.

Note on Android back button: override `PopScope` (Flutter 3.29 replacement for
WillPopScope) with `canPop: false`, `onPopInvokedWithResult` showing the same
cancel confirmation dialog, calling `controller.goBack()` if WebView `canGoBack()`.

**A. `lib/features/checkout/presentation/pages/payment_result_screen.dart`**

`PaymentResultScreen` is a `ConsumerStatefulWidget`.

Constructor:
```dart
const PaymentResultScreen({super.key, required this.orderId, required this.transactionRef});
final String orderId;
final String transactionRef;
```

`initState`: call `_pollOrderStatus()` immediately.

`_pollOrderStatus()`:
- Set `_isPolling = true`.
- Query: `Supabase.instance.client.from('orders').select('status, paid_at, total_cop').eq('id', orderId).single()`
- Map the returned `status` string to OrderStatusEnum (define a simple enum in this file:
  `payment_pending, payment_failed, paid, ...`).
- If status is `payment_pending`: wait 2 seconds then retry (max 5 retries, then show
  "Verificando con el banco..." state with a "Verificar ahora" button).
  PSE payments can take minutes — this covers the typical card/Nequi case; PSE users
  will see the "Verificando" state and be told to check the app later.
- If status is `paid`: set `_status = OrderStatus.paid` → rebuild → show success UI.
- If status is `payment_failed`: set `_status = OrderStatus.failed` → rebuild → show failure UI.
- On Supabase exception: show SnackBar and allow retry.
- Set `_isPolling = false`.

`build`:
Show one of three states:

1. Loading/polling state: centered Column with CircularProgressIndicator (neon green)
   + Text "Verificando tu pago...".

2. Success state:
   - Neon green animated checkmark (AnimatedContainer scale 0 → 1, 400ms curve
     Curves.elasticOut).
   - Text "¡Pago exitoso!" in white 24sp bold.
   - Text "Tu orden #QRA-... está siendo preparada." (show order number if available).
   - Ley 1480 retracto disclaimer (required by LGL-02 — show in this screen AND checkout
     review screen in a later iteration):
     Container with amber border, Text:
     "Productos personalizados (QR grabado) están excluidos del derecho de retracto
     conforme al Art. 47 num. 3 de la Ley 1480 de 2011."
   - PrimaryGlassButton "Ver mi orden" → navigates to placeholder route
     '/orders/{orderId}' (Phase 10 will implement the full screen; for now show a
     simple scaffold with "Orden en preparación").

3. Failed/error state:
   - Red X icon.
   - Text "Pago no completado" + "Por favor intenta de nuevo o usa otro método de pago."
   - PrimaryGlassButton "Volver al carrito" → Navigator.popUntil to cart screen.

Semantics identifiers: `payment_result_screen`, `payment_success_state`,
`payment_failed_state`, `view_order_button`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Wompi WebView → Flutter | NavigationDelegate intercepts redirect — URL parameters are observed but never trusted for order status |
| PaymentResultScreen → Supabase | Queries orders table with authenticated JWT; RLS enforces user_id = auth.uid() |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-11 | Spoofing | Forged qraft://payment-result redirect with status=APPROVED in URL | mitigate | PaymentResultScreen ignores URL params for status; always queries orders.status from Supabase directly |
| T-09-12 | Tampering | Deep link collision with auth flow | mitigate | qraft://payment-result checked explicitly in deeplink_service before generic handler; auth links use qraft://auth/* prefix |
| T-09-13 | Denial of Service | PSE flow leaves WebView open indefinitely | accept | PSE flows end in redirect eventually; user can cancel via AppBar back button with confirmation dialog |
| T-09-14 | Information Disclosure | order_id in deep link URL visible in logs | accept | order_id is a UUID, not PII; no financial data in URL; acceptable at v1 scale |
</threat_model>
