**A. Supabase Edge Function: `supabase/functions/create-payment-intent/index.ts`**

Deno function. JWT verification is ENABLED (default) — caller must send a valid
Supabase JWT in Authorization header (Flutter calls via `functions.invoke`).

Logic:
1. Parse request body: `{ cart_item_ids: string[], shipping: ShippingInput, idempotency_key: string }`
2. Extract `user_id` from the verified JWT (available as `req.headers.get('Authorization')` →
   decode JWT → sub claim). Use the service_role Supabase client for RPC calls so the
   function can access order tables beyond the caller's RLS.
3. Call `create_order` RPC:
   ```typescript
   const { data: orderId, error } = await supabaseAdmin.rpc('create_order', {
     p_user_id: userId,
     p_cart_item_ids: cart_item_ids,
     p_shipping: shipping,
     p_idempotency_key: idempotency_key,
   });
   ```
   If error.code === '23505' (unique_violation on idempotency key) → fetch the existing
   order by idempotency_key from payments.transaction_ref and proceed (idempotent retry).
4. Fetch order total from `orders` table: `SELECT total_cop FROM orders WHERE id = orderId`
5. Compute integrity signature (WOMPI Web Checkout spec):
   ```typescript
   const reference = idempotency_key;  // our transaction_ref
   const amountInCents = total_cop * 100;  // COP pesos → centavos
   const currency = 'COP';
   const raw = `${reference}${amountInCents}${currency}${Deno.env.get('WOMPI_INTEGRITY_SECRET')}`;
   const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(raw));
   const integritySignature = Array.from(new Uint8Array(hash))
     .map(b => b.toString(16).padStart(2, '0')).join('');
   ```
   Use `crypto.subtle` (Deno built-in) — NOT an external SHA-256 import.
6. Build the Wompi Web Checkout URL:
   ```
   https://checkout.wompi.co/p/?public-key={WOMPI_PUBLIC_KEY_FROM_ENV}&
   currency=COP&amount-in-cents={amountInCents}&reference={reference}&
   integrity={integritySignature}&redirect-url={REDIRECT_URL}
   ```
   Where REDIRECT_URL = `qraft://payment-result` (deep link handled in Plan 03).
   Read WOMPI_PUBLIC_KEY from `Deno.env.get('WOMPI_PUBLIC_KEY')` — set this secret too
   (even though it's public, keeping it in env allows environment switching without
   redeploying).
7. Return JSON: `{ order_id, transaction_ref: reference, integrity_signature, wompi_checkout_url, amount_cop: total_cop }`

Do NOT return private key, integrity secret, or events secret in the response.

**C. `lib/core/services/payments_service.dart`**

Singleton or injectable service. Single method:
```dart
Future<CheckoutSession> createPaymentIntent({
  required List<String> cartItemIds,
  required ShippingAddress shipping,
  required String idempotencyKey,
}) async {
  final response = await Supabase.instance.client.functions.invoke(
    'create-payment-intent',
    body: {
      'cart_item_ids': cartItemIds,
      'shipping': shipping.toJson(),
      'idempotency_key': idempotencyKey,
    },
  );
  if (response.status != 200) {
    throw PaymentServiceException(response.data.toString());
  }
  return CheckoutSession.fromJson(response.data as Map<String, dynamic>);
}
```

final createOrderProvider = FutureProvider.autoDispose.family<CheckoutSession, ShippingAddress>(
  (ref, address) async {
    final cartItems = await ref.read(cartItemsProvider.future);
    final cartItemIds = cartItems.map((i) => i.id).toList();

"Pay" twice before dismissal, the second watch re-uses the cached Future (autoDispose
keeps it alive while watched). On navigation retry the provider is recreated with a new
UUID — one transaction per attempt.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Flutter → create-payment-intent Edge Function | Authenticated JWT required; function uses service_role key internally |
| Edge Function env → Wompi secrets | Secrets accessed only via Deno.env — never returned to caller |
| ShippingScreen form → DANE validation | Client-side only (offline-capable); department/city are display values, not codes — no DANE API calls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06 | Tampering | Wompi INTEGRITY_SECRET in Flutter binary | mitigate | Integrity signature computed in Edge Function only; Flutter receives the pre-computed signature URL — never the secret |
| T-09-07 | Tampering | Amount tampered client-side | mitigate | create-payment-intent fetches total_cop from orders table (server-computed by create_order RPC) — client has no amount input in the Edge Function call |
| T-09-08 | Spoofing | Unauthenticated call to create-payment-intent | mitigate | Edge Function uses JWT verification (default); no JWT = 401 from Supabase gateway |
| T-09-09 | Denial of Service | Duplicate order creation on retry | mitigate | Idempotency key on payments.transaction_ref UNIQUE; duplicate insert returns existing order |
| T-09-10 | Information Disclosure | Shipping address in Crashlytics logs | mitigate | Never log ShippingAddress fields; catch PaymentServiceException and log only error code |
</threat_model>
